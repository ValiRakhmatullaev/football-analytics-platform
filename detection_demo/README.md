# Как работает детекция событий в загруженном видео

В этом каталоге — описание работы детекции голов, ударов и нарезок при загрузке видео.

## Что нужно, чтобы детекция работала корректно

1. **Мяч должен быть виден и детектироваться**  
   Сейчас при загрузке используется **цветовая детекция мяча** (оранжевый/жёлтый/белый). Если мяч маленький, размытый, нестандартного цвета или плохое освещение — событий может не быть или их будет мало.

2. **Частота кадров**  
   Пайплайн обрабатывает 1 кадр в секунду (`fps_sample=1.0`). Для удара/гола нужно, чтобы в нескольких подряд кадрах мяч был виден и двигался в сторону ворот.

3. **Классификация гола**  
   В клиппере голом считается событие типа **shot** (удар), у которого:
   - нормализованная позиция мяча по высоте **в зоне ворот**: `y < 20%` или `y > 80%` (верх/низ кадра);
   - уверенность события ≥ 0.45 (или ≥ 0.4 при очень близкой к воротам позиции).  
   Позиция `x`, `y` в JSON берётся с **конца траектории** удара (мяч ближе к воротам), чтобы гол правильно распознавался.

4. **Один гол — один клип**  
   Несколько кандидатов в голы в пределах 60 секунд объединяются в один момент (с максимальной уверенностью), чтобы не создавать несколько клипов на один реальный гол.

**Если голы не детектируются:** проверьте, что в JSON после обработки есть события с `event_type: "shot"` и что у части из них `y` близко к 0 или 100. Если «shot» вообще нет — скорее всего не детектируется мяч (попробуйте другое освещение/видео или используйте продвинутый пайплайн с YOLO: `video_analytics.pipeline_advanced`).

## Использование Roboflow/HF + BoT-SORT (YOLO, imgsz=1280, conf=0.25–0.3)

В коде это реализовано в **продвинутом пайплайне**:

- **Файлы:** `video_analytics/advanced_detector.py`, `video_analytics/pipeline_advanced.py`
- **Модель:** приоритет — футбольная модель (Roboflow **football-players-detection-3zvbc** или путь к `.pt` из HuggingFace/Roboflow), fallback — YOLOv8n (COCO).
- **Параметры:** `imgsz=1280`, `conf=0.28` (в диапазоне 0.25–0.3), трекинг **BoT-SORT** (`tracker="botsort.yaml"` в ultralytics).
- **Загрузка модели:**  
  - путь к `.pt`: переменная `ROBOFLOW_FOOTBALL_MODEL_PATH` или аргумент `model_path`;  
  - или Roboflow API: `ROBOFLOW_API_KEY` — тогда при первом запуске подтягивается датасет football-players-detection.

**Когда это используется:**

1. **Из командной строки** — всегда:
   ```bash
   python -m video_analytics.pipeline_advanced /path/to/video.mp4 --output-dir ./out --imgsz 1280 --conf 0.28
   ```

2. **При обработке загруженного видео в веб-интерфейсе** — только если включён продвинутый пайплайн:
   - В `backend/config/settings/` (или в `settings.py`) задайте:
     ```python
     USE_ADVANCED_VIDEO_PIPELINE = True
     # Опционально: путь к .pt модели (Roboflow/HF)
     ROBOFLOW_FOOTBALL_MODEL_PATH = "/path/to/football-players.pt"
     ```
   - Или через переменные окружения:
     ```bash
     export USE_ADVANCED_VIDEO_PIPELINE=true
     export ROBOFLOW_FOOTBALL_MODEL_PATH=/path/to/football-players.pt
     ```
   Тогда при нажатии «Обработать» для загруженного видео будет запускаться YOLO + BoT-SORT + детекция событий (shot/goal/pass/save), результат сохраняется в том же JSON и по нему создаются клипы как раньше.

## Цепочка обработки

1. **Загрузка видео** → бэкенд сохраняет файл, создаётся запись `VideoUpload`.
2. **Обработка** (`POST /api/analytics/videos/<id>/process/`):
   - Запускается `VideoAnalyticsPipeline` (модуль `video_analytics.pipeline`).
   - С видео снимаются кадры с частотой `fps_sample=1.0` (1 кадр в секунду).
   - В каждом кадре:
     - Детекция мяча (цветовая: оранжевый/жёлтый/белый).
     - По траектории мяча определяются события: **pass**, **shot**, turnover, set pieces.
   - События экспортируются в JSON (`events` с полями `event_type`, `timestamp_ms`, `x`, `y`, `confidence`).
3. **Нарезка клипов** (сервис `VideoClipper`):
   - Читается JSON с событиями.
   - Каждое событие классифицируется в момент для клипа:
     - **Гол** — если `event_type == "shot"`, уверенность ≥ 0.45 и мяч **в зоне ворот** (y &lt; 20% или y &gt; 80%), либо ≥ 0.4 при очень близкой позиции (y &lt; 10% или y &gt; 90%).
     - Чтобы не было нескольких «голов» вместо одного: все кандидаты в голы в пределах **60 секунд** объединяются — остаётся один момент с максимальной уверенностью.
   - Для каждого выбранного момента создаётся клип (ffmpeg): начало за 6 с до момента, конец через 12 с после (для гола).
   - Требования к нарезкам: гол — минимум 8 с, максимум 25 с; остальные типы — минимум 4 с, максимум 20 с.

## Почему раньше было несколько голов вместо одного

- Детектор выдавал **несколько событий «удар» (shot)** подряд на одном и том же эпизоде (по кадрам).
- Клиппер помечал как **гол** любой удар с высокой уверенностью рядом с воротами и создавал клип на каждое такое событие.

## Что изменено

1. **Гол в клиппере** (`backend/apps/analytics/services/video_clipper.py`):
   - Голом считается только удар с уверенностью ≥ 0.72 и мяч **очень близко к линии ворот** (y &lt; 6% или y &gt; 94%).
   - В пределах **60 секунд** оставляется только **один** гол (с максимальной уверенностью).

2. **Реже повторяющиеся удары** (`video_analytics/event_detector.py`):
   - После фиксации удара (shot) следующий удар не выдаётся в течение **5 секунд** (cooldown), чтобы один реальный удар не давал десяток событий в JSON.

3. **Нарезки**:
   - Минимальная длина клипа для гола — 8 с, максимальная — 25 с.
   - Перекрывающиеся клипы объединяются (остаётся один с большей уверенностью).

## Как проверить детекцию на своём видео

### Вариант 1: через веб (загрузка и обработка)

1. Загрузите видео через интерфейс (страница загрузки видео).
2. Запустите обработку (кнопка «Обработать» или `POST .../videos/<video_id>/process/`).
3. После обработки откройте страницу клипов: `/videos/<video_id>/clips`.
4. В списке должен быть максимум один клип типа «Гол» на один реальный гол в ролике (в пределах 60 с).

### Вариант 2: только пайплайн по пути к файлу

Из корня проекта (с установленными зависимостями `video_analytics`):

```bash
# Установка зависимостей
pip install -r video_analytics/requirements.txt
# или: pip install opencv-python numpy

# Запуск пайплайна (JSON с событиями в analytics_output рядом с видео)
python -m video_analytics.pipeline /path/to/your/video.mp4 --fps-sample 1.0 --output-dir ./analytics_output
```

В `./analytics_output` появится JSON с полем `events`. По нему видно, сколько раз детектор выдал `event_type: "shot"` и с какими `timestamp_ms`, `x`, `y`, `confidence`. Нарезки при этом не создаются — только события.

### Вариант 3: продвинутый пайплайн (YOLO + BoT-SORT + события)

Если установлен `ultralytics` и нужна детекция по трекингу (shot/goal/pass/save):

```bash
pip install -r video_analytics/requirements.txt
python -m video_analytics.pipeline_advanced /path/to/video.mp4 --output-dir ./out --fps-sample 5
```

В `./out` появятся `*_events.json`, `*_events.csv` и при необходимости аннотированное видео.

## Где лежит код

| Что | Файл |
|-----|------|
| Пайплайн при загрузке | `video_analytics/pipeline.py` |
| Детекция событий (мяч, удары, пасы) | `video_analytics/event_detector.py` |
| Классификация моментов и нарезки | `backend/apps/analytics/services/video_clipper.py` |
| Запуск обработки при нажатии «Обработать» | `backend/apps/analytics/api/video_upload.py` (VideoProcessAPIView) |

## Загрузка тестового видео в эту папку

Сюда можно положить **одно** тестовое видео (например `sample_goal.mp4`), чтобы воспроизводить поведение:

- Не коммитить большие файлы в git — добавьте в `.gitignore`:  
  `detection_demo/*.mp4` или `detection_demo/*.mkv`.
- Запуск пайплайна по нему:  
  `python -m video_analytics.pipeline detection_demo/sample_goal.mp4 --output-dir detection_demo/out`

После обработки в `detection_demo/out` будет JSON с событиями; по нему можно сверять, что детекция выдаёт один гол на один реальный гол в ролике.
