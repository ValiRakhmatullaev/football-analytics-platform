# Руководство по потоку данных и архитектуре

## 📊 Текущий поток данных

### 1. Загрузка видео через веб-интерфейс

```
Пользователь → Frontend (/upload) 
  → POST /api/analytics/videos/upload/
  → Сохранение файла на диск
  → Создание записи VideoUpload в БД
  → Возврат video_id
```

### 2. Обработка видео

```
Frontend → POST /api/analytics/videos/<id>/process/
  → VideoProcessAPIView
  → VideoAnalyticsPipeline.run()
    → Обработка видео
    → Детекция событий
    → export_to_json() → Сохранение в JSON файл ✅
    → export_to_django() → Сохранение в БД (если есть match_id) ✅
  → Обновление VideoUpload (статус, events_count, json_output_path)
```

## ✅ Что сохраняется

### 1. JSON файл (ВСЕГДА)
- **Где**: `analytics_output/<video_name>_events.json`
- **Когда**: Автоматически при каждом запуске `pipeline.run()`
- **Содержит**: Все обнаруженные события в структурированном формате
- **Зачем**: 
  - Бэкап данных
  - Отладка и анализ
  - Ручной импорт при необходимости
  - Аудит обработки

### 2. База данных Django (УСЛОВНО)
- **Где**: Таблица `events` в БД
- **Когда**: Только если указан `match_id` при загрузке
- **Содержит**: События как объекты Django Event
- **Зачем**: 
  - Использование в аналитике
  - API endpoints
  - Связь с матчами и игроками

### 3. Метаданные VideoUpload (ВСЕГДА)
- **Где**: Таблица `video_uploads` в БД
- **Содержит**: 
  - Статус обработки
  - Количество событий
  - Путь к JSON файлу
  - Путь к видео файлу
  - Ошибки обработки

## 🔄 Нужно ли перезапускать программу?

### ❌ НЕТ, перезапуск НЕ нужен!

**Почему:**
1. **Python загружает модули динамически** - изменения в коде загружаются при импорте
2. **Django использует autoreload** - автоматически перезагружает код при изменениях
3. **Video Analytics импортируется заново** - каждый раз при обработке видео

**Когда перезапуск НУЖЕН:**
- Изменения в моделях Django (нужна миграция)
- Изменения в настройках Django (settings.py)
- Изменения в зависимостях (requirements.txt)

**Когда перезапуск НЕ нужен:**
- ✅ Изменения в `event_detector.py` - загрузится автоматически
- ✅ Изменения в `pipeline.py` - загрузится автоматически
- ✅ Изменения в API views - Django autoreload перезагрузит

## 📋 Рекомендуемая архитектура

### Вариант 1: Всегда сохранять JSON + БД (РЕКОМЕНДУЕТСЯ)

```python
# В video_upload.py
result = pipeline.run()

if result["success"]:
    # 1. Всегда сохраняем JSON (бэкап)
    json_path = result["output_file"]  # Уже сохранен pipeline.run()
    video_upload.json_output_path = json_path
    
    # 2. Всегда сохраняем в БД (если есть match_id)
    if video_upload.match:
        pipeline.export_to_django()
    else:
        # Можно создать матч автоматически или предупредить пользователя
        logger.warning("No match_id - events saved only to JSON")
    
    video_upload.save()
```

**Преимущества:**
- ✅ Двойное сохранение (JSON + БД)
- ✅ JSON как бэкап
- ✅ БД для быстрого доступа через API

### Вариант 2: Только JSON (для MVP/отладки)

```python
# Сохраняем только JSON, БД опционально
result = pipeline.run()
# JSON уже сохранен автоматически
# БД сохраняем только если нужно
```

**Преимущества:**
- ✅ Простота
- ✅ Легко откатить изменения
- ✅ Можно импортировать позже

## 🎯 Рекомендации для вашего проекта

### 2. Улучшить сохранение в БД

**Решение**:

- Вариант B: Требовать `match_id` при загрузке (сейчас так)

### 3. Сохранять путь к JSON в VideoUpload ✅ (ДОБАВЛЕНО)

Теперь путь к JSON сохраняется в `video_upload.json_output_path` для удобного доступа.

### 4. API для получения JSON

Можно добавить endpoint для скачивания JSON:

```python
# GET /api/analytics/videos/<id>/json/
def get_json(self, request, video_id):
    video_upload = VideoUpload.objects.get(id=video_id)
    if video_upload.json_output_path:
        return FileResponse(open(video_upload.json_output_path, 'rb'))
```
